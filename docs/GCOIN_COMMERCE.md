# G币商品与支付接入

## 2026-10-25 联机路径更新

正式联机入口现由 `public/online/commerce.js` 和 `server/game/payment.ts` 接管；81个 payPoint 的 grantBy 改为 room，ID和价格不变。Room冻结上下文/随机结果，可信allowed回调只执行fulfill，完成后重读云账户，再通知客户端成功；重复订单不重复发货。下文client发货描述仅保留作单机历史记录，不适用于当前正式联机入口。官方Mock假订单验证通过，未发生真实扣款，也未部署此支付版本；真实支付与断网补发仍需部署后验收。旧client订单不转成Room订单冒领。完整状态见 [MULTIPLAYER.md](MULTIPLAYER.md)。

2026-10-25，用户授权应用81档价格并使用Builda G币支付。新售价为`max(100, 原价×5)`，保留145、495等非百位价格。商品排除默认木镐、禁售5天Skip、未做的跑步机跳级和已删除的赠礼。

## 入口与数据

- `h5-map/public/gameplay/commerce/catalog.js`：81档运行价格、类型、数量。
- `h5-map/builda.publish.json`：同一81档平台配置，`egg_<原商品ID>`，`grantBy: client`。
- `h5-map/tools/prepare_commerce.py`：从已批准价格、原Shop及镐子/拖尾配置重建这两个文件。拒绝静默替换不同的既有payId集合。
- `state.js`：购买条件、动态加速档位和各类发货；`service.js`：SDK支付、订单保存、幂等发货、claim和主动恢复；`runtime.js`：按钮绑定、支付期间输入锁定和交易结果。
- `cloud-save.js`：平台云存档；`paid-species.js`：6种付费动物的原配置属性，独立于普通区域抽取池。

Shop商品价格、下一档倍率价格，镐子/拖尾直购，成长列表Skip与Grow All，离线双倍入口已接通。界面G即G币。失败、取消不会发货；无SDK/云存档时返回不可支付，不产生模拟奖励。Shop提供“恢复购买”，不在进游戏时自动查询、不轮询。所有新增文字纯色填充加黑描边。

## 发货与范围

- 现金、速度数值、永久速度倍率：更新共享账户。倍率只允许逐档购买；镐子、拖尾和永久权益已拥有时不重复购买。
- 永久权益：2倍挥镐频率、2倍牧场现金、2倍蛋成长；已有成长蛋在购买成长权益时将剩余时间减半。
- 药水：购买即激活对应15分钟效果。同种重复购买续时，不重复叠加倍率。现金药水与永久现金权益相乘，训练药水与永久速度倍率相乘。
- 付费蛋：每份商品在购买意图中固定六物种抽取及变体，成功后才进入背包Eggs，使用现有放置/成长/孵化链路。种类概率70%、18%、9.9%、1%、1%、0.1%；Gold 5%、Diamond 1%。模型/动画复用既有资源，收益按原EggRewards的Cash、CashZone=9及稀有度基础重量。默认尺寸1、基础重量，成长60秒；原GrowByWeight的完整付费蛋尺寸/重量生成规则未恢复，不宣称与原服务端完全一致。库存不足时不打开支付面板。
- 单蛋Skip锁定购买时的蛋ID；Grow All锁定当时的未成熟蛋集合，不把后来新增的蛋算入。Grow All按剩余秒数总和选档，这是本次H5实现约定；原服务端汇总方式缺失。
- 离线双倍锁定当次待领取金额，支付期间普通领取被锁定；成功一次发放该金额×2，清除对应待领取额。
- Fallen Tokens记入余额，Shop分区标题显示余额；活动兑换系统仍未实现，本轮没有恢复已删除的Furnace或新增活动玩法。

## 存档与订单

SDK锁定0.12.1。支付仅调用`Builda.iap.showPayPanel(payId,{grantBy:'client'})`，不构造订单HTTP请求、不直接使用宿主桥。实际归属以返回值为准；room或未知归属不在客户端发货或claim。

支付前保存意图（商品、目标、随机结果），成功后保存带orderId及归属的收据，发货与applied标记放入同一快照提交，成功后才调用claim。重复回调检查标记；claim失败保留标记，恢复只补claim。支付成功响应期间中断、尚未写入订单映射时，主动恢复不猜测未知订单；用户再次点击原商品，由平台返回其未完成订单，继续原已保存意图。订单记录不按数量截断，存档接近上限时在支付前拒绝新购买。

新增privateKV键：`egg_account_head`、`egg_account_a_0..29`、`egg_account_b_0..29`，最多61键。数据使用Godot STRING Variant格式封装JSON（var_to_bytes/bytes_to_var兼容），每个值小于32KB、每批不超过30键。订单记录在快照内部，键为`pay_order_<sha256(orderId UTF-8)前48位小写hex>`；不将不透明orderId直接拼成KV键。

SDK setMany没有事务保证，所以先写非活动分块，回读逐块验证，再单键提交包含bank/count/hash的指针。旧活动快照在这一过程保持可读；head响应丢失后重试先查询实际活动bank。没有无限重试。普通游戏save合并为最多15秒一次云提交；支付各关键节点显式等待flush，claim不早于发货提交。所有键写满后保持有界，不持续新增KV键。

普通`python serve.py`预览在回环地址8765直接提供平台安装的官方mock SDK（只由预览服务器动态读取，不打入`public`发布包）；购买时同页出现“成功/失败”模拟支付面板，不扣真实G币。旧浏览器本地存档仅在此回环预览的mock云档为空时导入一次，原localStorage不删除；后续使用mock privateKV保存。Builda App中的真实平台云存档按平台用户隔离，不自动导入未绑定身份的旧localStorage。当前正式画面仍用客户端账户，此方案不等于Room权威发货；今后正式接入Room持久化应重新设计订单归属及资产迁移，不能混用两条发货路径。privateKV为最后写入胜出，无跨设备CAS，不宣称解决同账户多设备并发存档冲突。
