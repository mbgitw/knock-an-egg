# 守卫导航实现（2026-10-25）

目标：消除巡逻阶段的实时搜索，动态追击持续获得有效路线，并让所有守卫的总工作量和快照体积可预测。保留原移动速度、警戒时长、碰撞、抓捕及安全区规则。

## 方案

- 构建阶段读取原胶囊净空网格，预计算合法有向边、弱连通分量，以及每个守卫区域的双向可行巡逻树和12个巡逻锚点。运行时不再扫描整个地图或随机尝试12次A*。巡逻从当前格子沿树到达随机有效锚点，闲逛分布由连续随机点改为覆盖区域的预选锚点。
- 追击先检查连通性、复用缓存路线，再尝试逐格验证边的直达路线；不跨越原烘焙边，也不平滑穿过细柱或封闭角。必要时先给出有效巡逻树走廊，同时计算更短路径。
- 动态A*用二叉堆和整数格子编号；一次更新所有守卫合计最多600次出堆（包含过期项），所有请求先分得24次工作，再将剩余额度分配给追击和等待较久的请求。预算耗尽保留堆、代价和父节点，下次续算。
- 玩家移动不反复取消同一追击对象的请求；已有有效路线继续使用。新路径完成后从守卫当前位置修复接入，追击对象改变或状态改变才作废旧任务。不可达目标有短退避，避免逐帧重试。
- 服务端路径存格子编号，实际移动时才取当前路点坐标。保留旧快照的三维路点兼容；不再逐帧复制整串三维对象。
- 单任务最多2048个已发现节点、4096个堆元素、1024个结果路点。十个任务最坏构造JSON为1,578,601字节（不含其他世界状态），低于4MiB快照上限，仍需与玩家资产总量合并评估。

## 迁移与协议

`state.guards[*].navigationState` 保存计算中任务、路线缓存、退避和调度时钟；无时钟/随机数/函数闭包进入快照。共享导航图是固定生成数据。旧快照缺少该可选字段时延迟初始化，构造恢复对象不额外消耗宿主随机数。`roomTransferRecovery=safe`已通过。

不改变客户端消息或账户结构，兼容三问均为是，`onlineCompatibilityRevision=2`保持。此轮为服务端优化，沿用已有客户端草稿。

## 已验证

223项现有回归、19项联机、14项导航/预算专项通过；类型检查、官方恢复检查、同源码Mock双身份进房/基线/退出/空房回收通过。追击过程中逐tick序列化/恢复与不中断执行的轨迹完全一致；路线消费使用独立数组，避免修改缓存。

10个真实区域模拟600秒，全部守卫移动且巡逻A*为0；1,320组实际巡逻锚点之间的独立追击测试立即取得有效走廊，增量优化最多2个更新周期完成（单个请求测试，不是10个并发请求的时延保证）。全部巡逻树边验证有双向胶囊净空。验证移动目标不重置任务、墙体/封闭角、请求公平性、JSON中途恢复、十区域警戒/抓捕/安全区回位及有界快照。

同地图/种子/10分钟/每tick序列化恢复的最新单次Node基准：上一版600节点/4搜索限流实现894ms、2,565次寻路请求、692次实际开始、178,078个节点扩展；新版412ms，巡逻无A*，守卫快照5,895字节。两版巡逻路线不同；这只是本地处理耗时，不能换算为线上fuel或手机fps。实际平台fuel、真机长期存活及多人复杂追击仍需部署后验证。

## 技术依据



本项目使用已有离散胶囊净空网格实现这些原则，没有引入Unity依赖，也没有切换引擎。
