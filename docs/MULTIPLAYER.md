### 实施范围与权责

沿用 H5 + Three.js，选用官方 H5 Online SDK 0.18.0、TypeScript Room SDK 0.14.11，统一发布锁 0.12.1。`builda.online.json` 对应 `server/game/room.ts`、`public/online/config.json` 与 `builda.room.local.json`。入口 `pasture-world`，公共自动找房，1组×7席；满房新建，有空位继续加入，断线暂留席位。未增加机器人、私人房、排名、匹配确认或聊天。牧场是持续世界，没有比赛结束/重开两局流程；显式退出调用 SDK leave，空房交给平台回收。

Room 负责蛋与 Titanic 的时钟/血量/随机奖励、拾取竞争、携带掉落和入库、守卫判定、球棒目标/击飞、现金与力量、训练、装备购买、牧场等级/放置/收益、合成/孵化、图鉴领取及付费交付。玩家只提交意图；不能提交余额、奖励、伤害或任意被击玩家。动物落地约6.15秒可拾取，观望结束约8.65秒开始45秒倒计时；长按1.4秒，携带暂停倒计时。

本机仍负责人物操作与地图碰撞，Room 检查位移预算、边界、序号和频率；这不是服务端完整物理或强反作弊。守卫地面采用烘焙网格近似，真实地图边缘、弱网击飞与跨实例迁移仍需线上验收。公共跑步机事件的新增运营触发入口未实施。

### 数据判定与风险

推荐“本机即时移动 + Room轻量检查；共享资源/收益由Room统一判定”：

- 移动：客户端上报位置/朝向/移动状态；Room校验有限数值、边界、速度上限、序号和发送频率，截断或拒绝异常更新。客户端立即响应输入，其他玩家插值。不在Room逐帧运行整张GLB的物理。此方案仍可能被篡改位置或利用简化碰撞，不是完整移动反作弊。
- 蛋命中/购买/升级/训练/出售：只接受意图；Room根据自身装备、余额、蛋代次、距离、冷却和时钟仲裁，重算数值/奖励，不信任客户端直接提交的金额、伤害或收藏。每个关键请求带可去重序号，重试不重复发奖。
- 蛋刷新/守卫：Room维护轻量实体和导航数据，不加载渲染模型。状态/计时和随机结果统一；捕获只由Room确认。
- 外观与挥击事件：验证装备所有权和频率后转发；粒子/骨骼/镜头纯本地。
- 存档：个人数据用Builda支持的云数据契约，余额等业务状态若由Room管理必须走Room的玩家数据事务。旧本地存档保持原件，不直接信任并上传为权威资产；迁移策略在实现前明确记录。

这比纯转发占用更多Room计算和快照预算，但能避免多人同时敲蛋各自发奖、越权升级他人牧场、客户端直接改余额。每帧完整物理服务器重算更重，本方案不采用。具体CPU/带宽结果需实测，不能用方案估算冒充容量验证。

### 从开始实施的性能预算



1. 本人输入与渲染保持本地帧率。移动上行上限15Hz，静止阈值抑制加低频心跳；远端100–150ms插值缓冲，最多约200ms有界外推，过期停止外推。带序号，丢弃旧帧。
2. 人物状态打包数字ID、量化坐标/朝向/标志，不发JSON整场景或骨骼。变化时可靠发送装备/牧场/经济事件，连续位置使用SDK不可靠通道，旧位置不可靠重发堆积。
3. 守卫逻辑拟10Hz，远区降低导航重算和广播；按附近玩家/区域兴趣发送状态。场景渲染仍做插值，模型动画与网络tick分离。
4. 230个蛋初次/重连分批快照，版本号对齐后才解锁交互；进入新区补该区快照。日常只发变化的血量、破碎/奖励、刷新记录，静止蛋不周期全量广播。
